# Project Definition Decision Guide

开始立项时读取入口与 G0 审阅；其余部分在判断项目形式、叙事方式、调研等级或下一阶段时按需读取。类别用于澄清创作方向，不是必须填满的标签系统。

## 入口与本次交付范围

- 公共流程/Skill 优化属于仓库维护，不创建项目简报或项目目录。实际创作先确认是新项目、已有项目续作还是方向探索；已有批准不因进入新会话失效。
- 沿用用户已经确定的项目与范围。项目归属无法判断时先确认 Project ID；只有确定新项目后才拟编号。探索阶段可先比较方向，不替用户锁定正式项目。
- 范围未说明时，正式立项前优先询问是否只交付剧本、分镜文字、提示词，由 RunningHub 或其他平台生成和剪辑，并推荐这种分工。一次只解决最影响正确性的缺口，已有答案不重复询问。
- 用 `Delivery Scope` 记录本次产物、是否包含实际媒体和终止阶段。例如「CONTENT_ONLY：剧本、分镜与生成提示词；终止于 Stage 13；真实资产与画面审核待平台验证」。PREPRODUCTION 也须明确图片是否由本次生成，不能等同于内容交付。
- 三类 Execution 字段只记录操作路线；未知模型、画幅、音色或手动交接位置可以留 OPEN，不阻断不依赖它们的研究和故事开发。任何路线均不替代具体生成授权。

## G0 项目定义审阅

填写 Brief 后，先用已有内容复述「关注谁/什么、处于什么情境、希望观众经历什么」，核对它是否忠实于用户原意，再检查：

1. **范围清楚：** 本次交付物、终止阶段、发布结构及真实/虚构边界是否足以选择下一阶段？未知片名、模型或平台不自动成为阻断项。
2. **创作核心具体：** Project Expression 能否用 1–2 句让人理解主体、基本情境与核心体验？Emotional Thesis 是否指向具体关系或经验，还是只写“震撼、感动、电影感”？受众、观看情境与所需背景是否影响表达选择？缺乏依据时保留 OPEN 并标明后续需要澄清，不凭空补悲剧、意象或结局。诗性、观察式作品不强求主角欲望、对抗或成长弧；方向已明确时不重复比较，探索时按表达重点、观众体验、独特之处和制作代价比较候选。
3. **约束可共存：** 时长、人物/事件数量、对白需求与用户必须保留项是否存在明显冲突？已有预算、投入时间或期限能否支持预期规模？关键 AIGC 可行性假设是否标出创意影响与最晚验证阶段？冲突先给出具体取舍及其影响，不静默删人物、加长片长或改写形式；本阶段不反推镜头数量、不执行样片、不把平台宣传视为成功证据。预算、受众或模型未知且不影响当前交接时可以留 OPEN。
4. **研究问题可执行：** 待核实项是否说明需要确认什么、会影响哪个创作决定？把关键未知交给 Research，不把本阶段常识或假设写成已核实事实。
5. **交接有依据：** 下游能否凭 Brief 识别必须保留、可探索与不可宣称内容？原作未读范围、参考未分析部分、候选 Method 未验证状态必须保留。

在现有 Decision Register 的 `G0 Review` 中记录审阅依据、阻断项和最晚解决阶段；READY 只表示定义可交接。存在互相冲突的定义则 RETURN，必要用户决定未定则 OPEN；常规字段缺口自主整理，不能把自检写成用户批准。已有项目只复核本次改变及受影响范围，不要求重新立项或重复批准。

工艺参考：[Runway 官方教学方案](https://runwayml.com/assets/runway-education-curriculum-packet-dec-2025.pdf) 将项目概念、受众、预算与时间纳入提案；[StudioBinder 创意简报](https://www.studiobinder.com/blog/best-creative-brief-template-video-agencies-free-download/) 区分受众、目标与调性；[Runway Cinematic Brainstorm](https://help.runwayml.com/hc/en-us/articles/50984345992467-Cinematic-Brainstorm) 展示确定视觉方向前的多方案探索。本 Skill 借鉴其概念沟通和比较思路；公开前期教程中的样片、分镜与生图仍归后续阶段，不能变成立项的强制生成任务。

## 何时先问一个问题

只有缺口会改变项目性质或使整份简报建立在错误方向上时，才先提问。优先级最高的情形包括：

- 用户只说想做 AIGC 电影、短片或某个题材，但没有说明是单支成片、系列短片还是连续剧情剧集；
- 同一想法既可能是真实纪录，也可能是剧情虚构；
- 内容涉及真实人物或事件，但用户是否要求事实准确尚不清楚；
- 两个互斥的硬约束会导向完全不同的项目；
- 用户提到“参考某作品”，但无法判断是喜欢其主题、叙事还是视觉。

一次只问影响最大的一个问题。若 Release Format 未知，且没有更高风险的真实性问题，优先确认它。片名、具体年龄、画幅、次要人物和结局通常可以保持 `OPEN`，不应阻断简报。

## Release Format & Series Architecture

- `Standalone Short`：单支短片完成核心体验，不为续集预留强制悬念。
- `Short-form Series`：多支短片共享主题、角色或世界；再选择 `Standalone Episodes / Shared World Episodes / Continuous Serial / Hybrid`。
- `Episodic Anthology`：每集人物或故事可更换，以共同主题、时代、地点或形式连接。
- `Serial Narrative Series`：人物和因果跨集连续，单集需要局部推进但不必独立闭环。
- `Feature or Long-form`：一个长篇成片；只有用户明确提出时采用。

默认提问：`你希望先按哪种形式开发：单支短片、每集独立的系列短片，还是连续剧情剧集？`

如果用户回答“系列”，但没有说明单集关系，再追问一次最小问题：`每集希望独立成篇，还是人物和剧情连续推进？` 不要在同一轮一次抛出多张制作问卷。

发布结构影响下游，但本阶段只记录接口：

- 单支短片：一个 Story Core、一条主要变化和一个结局方向。
- 独立系列：需要系列共同承诺、单集变化原则和可复用资产，但不生成选集清单。
- 连续剧集：需要跨集 Story Engine、角色持续变化范围和季级问题，但不生成分集大纲。

## Film Form

- `Narrative Fiction`：人物与事件主要由创作构成。
- `Historical Fiction`：以特定历史时期、人物或事件为基础，但包含明确虚构。
- `Documentary / Humanistic`：以真实主体和现实观察为核心，不为满足剧情结构而编造事件。
- `Docu-fiction`：真实材料与设计、重演或虚构结构有意结合；必须说明边界。
- `Essay Film`：通过观点、旁白、材料和意象探索主题，不依赖完整情节。
- `Experimental`：形式、感知或结构实验高于传统叙事目标。

如现有信息不足以在纪录与虚构之间判断，先提问，不自行选择。

## Narrative Mode

选择一个主要模式；确有必要时增加一个辅助模式：

- `Plot-driven`：目标、事件、因果和转折推进。
- `Character-driven`：人物选择、关系与内在变化推进。
- `Observational`：观察日常行为、空间和时间，不制造强剧情。
- `Memory-driven`：以回忆、时间断层和主观经验组织。
- `Essayistic`：以观点、旁白、档案或意象关联组织。
- `Investigative`：通过调查、证据和逐层发现推进。
- `Poetic`：以情绪、声音、节奏和意象关系主导。

模式描述“如何组织观看体验”，不能只根据题材或视觉风格判断。

## Reality / Fiction Level

- `Factual`：人物、事件和陈述以可核实真实性为基本承诺。
- `Fact-based with Reconstruction`：事实为核心，包含明确重演或重构。
- `Historical Fiction`：历史环境或事件真实，主要戏剧表达包含虚构。
- `Contemporary Fiction`：现实世界中的虚构人物与事件。
- `Speculative Fiction`：存在未来、替代现实或超现实设定，但仍需内部一致。

不要用“写实风格”代替真实性承诺；画面看起来真实，不代表内容是事实。

## Core Contrast & Emotional Turn

`Core Contrast` 描述项目中两个彼此照亮、冲突或改变含义的状态。优先识别：

- 时间反差：过去的承诺与后来的结果；
- 价值反差：人物想守住的价值与现实要求；
- 关系反差：同一人物在不同关系中的不同选择；
- 处境反差：贫困与富足、公开身份与真实处境、日常与异常；
- 认知反差：观众先形成的判断被后续证据重新解释。

反差不是“必须有反转”。如果项目以观察、氛围或持续状态为主，可以写 `Not Contrast-led`。不得为了填字段自行加入死亡、背叛、恶人、秘密身世或灾难。

`Emotional Turn` 用 2–4 个方向词描述观众体验的变化，例如“温暖 → 突然失落 → 余痛”。它不能代替故事结构，也不能把尚未决定的结局写成事实。

## Research Dependency

- `Very High`：真实历史事件、真实人物、纪录承诺、敏感社会议题或事实错误会改变项目含义。
- `High`：明确年代、地域、职业、文化或社会环境是故事成立的基础。
- `Medium`：主体为虚构，但可信度依赖特定专业、科学、地域或生活细节。
- `Low`：主要依赖虚构人物与情感关系，事实细节不会显著改变项目核心。

片长短不等于调研依赖低。科幻项目可以在现实研究上较低，但在科学或世界设定一致性上仍需要专题研究。

`Required Topics` 只列会影响创作判断的主题，不列百科全书式清单。

## Next Stage Routing

G0 READY 后，按以下优先级只选择一个阶段：

0. `Source Intake`：原作覆盖不足以支持当前项目判断，先补实际阅读范围；不能凭简介或记忆进入完整改编。
1. `Research`：Research Dependency 为 `High` 或 `Very High`，或存在会改变人物、世界与情节基础的关键事实缺口。
2. `Story Development`：事实基础足够，Premise、Central Question 和基本主体已经可用，需要发展事件、结构或完整故事。
3. `Character Development`：事实与项目形式已足够稳定，且人物关系、动机或视角是下一步能解除的主要创作瓶颈。

不要因为用户提到“画面不错”就跳到视觉或镜头阶段；先确保项目定义可以解释为什么以及为谁使用这些方法。

## Creative References

把参考信息转换为创作意图，而不是模仿指令：

- “喜欢这部片”不够具体，应保留为待分析问题，或在必要时询问用户喜欢的维度。
- 用户给出具体片段或时间码时，原样记录；已核验参考素材时可以补充真实时间码并标明它来自分析，不得凭印象制造精确位置。
- 优先记录节奏、情绪路径、叙事功能、关系组织和视觉原则等可迁移品质。
- 分开写清 `Why It Works` 与 `Transferable Mechanism`：前者解释参考片段，后者说明如何换成新的角色、事件、道具或时代继续使用。
- 明确排除具体剧情、标志性角色、独特世界观和可识别构图的复制。
- 深入的片段拆解、跨案例比较和 Method 晋升交给 `film-video-method-curator`，本 Skill 只记录项目意图与采用决定。

## Method Fit Check

- 用户只提供参考但没有要求跨项目复用时，保留为 Creative Reference，不自动采用 Method。
- 用户点名已有专项 Skill，或明确要复用已沉淀方法时，检查当前项目是否落在 `Use When / Validated For` 范围。
- 候选 Method 可以进入 `PILOT`，不能标为已验证；`REVIEW_REQUIRED / RETIRED` 不得默认采用。
- 可以组合多个 Method，但必须写明各自 Adoption Scope 和 Controlled Fields；同一字段存在冲突时保持 OPEN 或请求用户裁决。
- Method 会改变故事因果、人物选择或事实承诺时，必须从对应创作上游开始采用，不能只在视觉或 Prompt 阶段套用。
