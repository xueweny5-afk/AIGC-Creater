# Film Project Director Evaluation Rubric

每项按 `0–2` 分评分：`0` 为不满足，`1` 为部分满足，`2` 为清晰满足。总分至少 `18/20` 且没有硬失败，视为当前版本通过。

若案例应在生成 Brief 前提出一个关键问题，则使用“阻断分支”验收：问题必须唯一、直接决定项目性质，并且在回答前不得输出完整 Brief。满足这三项且没有硬失败即为通过，不计算数值总分。

## 评分项

1. **Intent Preservation**：用户原始意图、限制和强调点被准确保留。
2. **Information Discipline**：能区分 `USER_FACT / INFERRED` 与 `LOCKED / OPEN / ASSUMED`。
3. **Form and Mode Fit**：影片形式与叙事模式依据输入判断，没有机械套用单一结构。
4. **Release Architecture**：主动确认单支、独立系列或连续剧集，并正确记录单集关系与数量范围。
5. **Research Gate**：调研等级和主题与事实依赖匹配，没有用片长或类型替代判断。
6. **Reference Handling**：参考作品被转换为可迁移品质，并明确不可复制内容。
7. **Contrast and Emotional Turn**：反差来自输入中的真实关系，情绪转折清楚但没有被扩写成未经确认的剧情。
8. **Boundary Control**：没有进入 Treatment、分集大纲、剧本、镜头、分镜或生成 Prompt。
9. **Handoff Quality**：固定字段完整，未决项清楚，首要下一阶段唯一且理由成立。
10. **Audio / Language Intent**：语言、对白/旁白、环境声、音乐、口型和交付变体被前置记录；未知项保持 OPEN 且不误阻断前期。

## 硬失败

出现任一项即不通过：

- 更改或忽略用户明确锁定的条件；
- 新增会改变项目本质的重大人物、事件、历史事实、反转或结局；
- 把 `ASSUMED` 或外部常识写成用户已确认事实；
- 在应先区分纪录与虚构等高影响情形时直接猜测并生成完整简报；
- Release Format 缺失时自行锁定单支或剧集，或把“适合系列”写成用户决定；
- 输出完整剧情、逐场内容、镜头设计或图像/视频 Prompt；
- 将参考作品转化为复制其剧情、角色、世界观或可识别视觉表达的指令。
- 为制造反差而擅自加入死亡、背叛、贫富逆转、秘密身世或灾难等重大情节。
- 声音或语言未确定时擅自锁定模型，或无依赖地阻断前期开发。

## 执行记录

每次评测记录：案例、日期、总分、硬失败、主要偏差和下一轮最小修改。只根据重复出现或确实影响任务完成的问题修订 Skill，避免为单个案例堆叠规则。
