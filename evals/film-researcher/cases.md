# Film Researcher Evaluation Cases

这些案例验证研究决策、来源纪律和候选排序，不要求输出逐字一致。真实网络测试必须记录运行日期与实际可用来源。

## Case 1：八王之乱历史瞬间

**输入重点**

- Film Project Brief 要求寻找影响重大或具有代表性的历史瞬间。
- 用户提供一个包含西晋笔记和书籍摘录的 Obsidian 范围，并允许网络补充。

**应观察到**

- 使用 History & Real Events 模式，先检索指定笔记，再用原始史料、学术研究和权威机构交叉核实。
- 先建立原始史料、断代史与专题研究的阅读路径，再形成候选；历史小说或影视若被使用，只能列为创作参考。
- 明确区分史料记载、现代解释、通俗叙述和文学演绎。
- 没有可靠依据的对白或“名场面”不得标为 `CONFIRMED`。
- 候选按门槛进入优先、备选或暂缓；趋势模式默认关闭。

## Case 2：即将消失的老菜市场

**输入重点**

- 人文观察项目，不希望强行煽情或制造冲突。
- Obsidian 中有地方记忆和采访摘录，网络有城市公开资料。

**应观察到**

- 使用 Humanistic & Real-world 模式，区分机构资料、统计、媒体与个人经验。
- 能补充地方志、社会研究、行业资料或高质量非虚构作品，并诚实标记实际阅读范围。
- 不把单个采访概括为整个群体，不新增拆迁阴谋、悲剧或强反转。
- 候选可以围绕空间、劳动、人物关系或时间节律，而非必须依赖剧情事件。

## Case 3：最后一名气象观测员

**输入重点**

- 科幻短片需要研究气象工作、海上设施和自动观测。

**应观察到**

- 使用 Science & Sci-Fi 模式，把内容分为 `ESTABLISHED / EMERGING / SPECULATIVE`。
- 不用公司宣传或单篇论文代表科学共识。
- 明确现实限制与艺术许可，不把创作假设写成当前事实。
- 如研究优秀科幻作品，只提炼其如何把科学限制转化为思想实验，不把小说设定当科学依据。

## Case 4：原创修仙世界

**输入重点**

- 用户希望参考传统文化和类型惯例，但不复制现有作品。

**应观察到**

- 使用 Myth, Xianxia & Fantasy 模式，区分古典来源、地域版本、网文惯例和原创设定。
- 先建立文化根系资料，再选择用户指定或有代表性的优秀玄幻、修仙小说形成小型参考作品组，并标记实际覆盖程度。
- 不把神话当作可验证历史，不复制具体 IP 的体系、人物、情节或视觉表达。
- 输出每部作品的可迁移品质与不可复制项；候选研究方向体现可迁移的文化原则和类型方法，而不是现成世界观拼接。
- 将实际读到的内容、对其作用的解释、可迁移机制和本项目待验证假设分开；未做小样前不把参考经验写成已证实规则。
- 候选使用 `Research-grounded Summary`，分开标注文化依据、类型参考与原创提议；原创设定不因无法被“证实”而机械降分，但缺少文化根系、类型区分或挪用检查时必须降低 `Evidence Confidence`。

## Case 5：治愈短片平台趋势

**输入重点**

- 用户明确要求了解最近 30 天 B站、抖音的治愈类短片信号。

**应观察到**

- 按需启用 Trend & Audience，记录日期范围、成功与失败平台、缓存状态和数据限制。
- 不虚构互动数据或全平台共识；数据稀疏时标记 `Weak` 或 `Insufficient`。
- 趋势信号独立展示，不改变候选核心总分，也不覆盖用户创作意图。

## Case 6：发布结构保持开放

**输入重点**

- Project Brief 已允许试跑一个宗门原型，但 `Release Format / Series Architecture` 仍为 `OPEN`。

**应观察到**

- `Research Scope Unit` 使用 `Prototype Unit`。
- 只研究当前原型成立所需的文化、类型和制作依据，不生成选集、季弧或长期角色研究计划。
- 候选可以注明扩展潜力，但不能把潜力写成用户已决定制作系列。
- Story Development Handoff 明确保持范围开放。

## Failure Scenarios

- Obsidian 未运行：记录不可用，在已允许网络补充时继续，否则停止。
- 指定文件夹为空：不得扩大扫描整个 vault，先记录范围为空。
- 本地笔记与网络冲突：标记 `DISPUTED` 并保留双方来源。
- 多个网页均转载同一来源：按一条证据链处理。
- 只能访问小说简介或评论：标记 `Synopsis / Detailed Review / Metadata Only`，不得声称通读原作。
- 创作作品被当作历史、现实或科学证据：视为失败，必须改为 `REFERENCE_ONLY`。
- 将二手简介或记忆中的内容写成亲见证据，或把研究者解释伪装成作品事实：视为失败。
- 只有单一可靠来源：标记 `SINGLE_SOURCE`，不能进入证据充分的优先候选。
- 平台接口或公开页面不可用：明确降级，不生成虚假的播放量、热度或用户情绪。
