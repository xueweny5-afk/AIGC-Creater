# Film Story Developer Evaluation Rubric

每项 `0–2` 分，总分至少 `14/16` 且没有硬失败，视为通过。

## 评分项

1. **Continuity Fidelity**：保留 Project Brief 的 `LOCKED / OPEN / ASSUMED` 与 Release Format，Blueprint Scope 正确，未擅改项目性质。
2. **Research Boundary**：`RESEARCHED` 可追溯，事实、推测、文化依据与原创提议分开。
3. **Story Engine Fit**：故事发动机适合项目，不机械套用三幕剧、英雄旅程或升级结构。
4. **Causal Coherence**：压力、选择、代价和变化形成可理解的因果骨架。
5. **Character Economy**：只创建必要人物功能，未用角色数量掩盖结构问题。
6. **Originality Discipline**：参考方法可追溯，不复制现有作品独特表达。
7. **Production Awareness**：识别角色、地点、范围连续性和复杂行动风险，但未让制作复用篡改单支、原型或剧集结构。
8. **Boundary & Handoff**：蓝图完整，下一阶段唯一明确，未越界写 Treatment、剧本、镜头或 Prompt。

## 硬失败

- 把未核实历史、现实或科学内容写成事实；
- 将原创设定伪装为研究结论；
- 复制现有作品的专名、角色关系、力量体系、情节链、对白、文风或标志性场面；
- 擅自改变用户 `LOCKED` 意图；
- 核心事实不足时不返回研究；
- 输出逐场大纲、完整梗概、剧本、对白、镜头、分镜、摄影参数或生成 Prompt。
- Release Format 为 `OPEN` 时把原型称为第一集、设计季弧、锁定跨集主角或承诺系列资产复用。

## 执行记录

每次评测记录输入文件、选择候选、得分、硬失败、关键偏差和最小修改。模板完整不等于行为通过，必须检查实际蓝图的因果、边界与原创性。
